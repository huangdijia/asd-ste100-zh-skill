# asd-ste100-zh：中文技术文本保真与清晰化

借鉴 [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill) 的去歧义原则，为中文技术写作重新设计的技能规则。

**先保持原意，再减少歧义。** 不为了句子更短而丢失条件，也不把推测改成事实、建议改成命令。

> 这是非官方中文适配，不是 ASD-STE100 的中文标准、译本或认证工具。技能名称中的 `asd-ste100` 表示来源和灵感，不表示 ASD 授权、认可或中文合规保证。

## 适用场景

- 工具与 API 说明
- 错误消息、状态报告
- 操作步骤、代理间指令
- 提示词、README、PR 说明中的技术段落

不用于以声音、情感或说服力为重点的创作与营销文案；不代替技术事实核验或专业合规审查。

## 怎么使用

### 直接作为改写规则

将 [SKILL.md](SKILL.md) 的规则提供给你使用的助手，再提交待改写文本。例如：

```text
请按 asd-ste100-zh 规则改写下面的工具说明。
保留所有事实、数字、条件、作用范围、否定、例外和情态。
不要新增步骤；发现重要歧义时先标注待确认。

[在此粘贴原文]
```

需要看改动时，补充：

```text
请给出原文、改写、对应规则编号，以及逐项保真核对结果。
```

### 作为技能使用

本项目的技能名是 `asd-ste100-zh`，仓库为 [huangdijia/asd-ste100-zh-skill](https://github.com/huangdijia/asd-ste100-zh-skill)，入口是 [SKILL.md](SKILL.md)。如果所用工具支持目录式 `SKILL.md` 技能，按该工具的导入方式导入本目录，并保留随附参考文件和 LICENSE。

使用 skills CLI 时，可在希望安装技能的项目目录中运行：

```bash
DISABLE_TELEMETRY=1 npx skills add huangdijia/asd-ste100-zh-skill
```

也可以下载仓库后，手动导入支持目录式技能的工具。具体加载方式由所用工具决定。以上是供使用者选择执行的安装说明；仓库不会自行安装技能或修改默认设置。

## 一个例子

原文：

> 如果校验通过，保存文件并发送通知。

改写：

> 如果校验通过，执行以下操作：
> - 保存文件
> - 发送通知

两项动作仍共享同一个条件。原文没有规定先后，所以这里使用无序列表。

不能改为：

> 如果校验通过，保存文件。发送通知。

这种拆句让“发送通知”脱离明确条件，表面更短，意思却可能改变。

## 核心规则

1. 保留主体、动作、对象、状态和事实。
2. 保留数字、单位、区间端点、阈值、量词和适用范围。
3. 保留且/或、必要/充分条件、否定、例外和分支关系。
4. 保留时间、完成状态、顺序、并发、因果与确定程度。
5. 不把“可能、应、建议、必须、可以”当作可互换的语气词。
6. 不猜执行者、原因、时限、阈值或失败处理策略。
7. 术语只有在确认同义时才统一；不合并“检查、验证、确认”等不同动作。
8. 保护代码、API、参数、路径、URL、错误码和精确匹配字符串。
9. 中文短句是软目标，不套用英文词数、词性、时态或批准词典。
10. 只做必要修改，逐义双向核对；歧义待确认，不用猜测补全。

## 两种模式

- **步骤模式**：编辑读者要执行的操作，保留条件、约束与执行关系。
- **说明模式**：编辑系统行为、错误解释、状态与背景，不将描述自动改成命令。

两种模式都必须保真。默认只输出改写正文；必要时另列待确认项。用户请求时提供 diff 或规则对照。

## 能力边界

本项目目前提供写作规则和人工/模型验收材料，不包含中文自动 linter。验收用例不是机器测试已通过的声明。模型仍可能误读原文，关键技术文本应由了解实际系统的人复核。

原项目的英语 linter 不证明原文与改写语义等价，也不能直接作为中文合格检查器。本项目不复制 ASD 官方批准词典，不保证任何官方 STE 合规。
